# عمليات مندوب المبيعات الميدانية — Phase 3F

## قاعدة الواجهة

هذه المرحلة لا تعيد تصميم واجهة Flutter المعتمدة. يبقى مسار اليوم كما هو:

`الانطلاق ← الزيارات ← الفواتير ← التحصيل ← العودة ← الإقفال`

يقتصر العمل في Laravel على توفير البيانات الرسمية والعقود التي تربط الواجهة الحالية.

## العقد التشغيلي

- رحلة مبيعات واحدة لكل مندوب وخط وتاريخ.
- تتحول قائمة عملاء الخط الفعّالين إلى زيارات مخططة مرتبة.
- تبدأ الرحلة ثم تبدأ زيارة واحدة فقط في كل لحظة.
- تنتهي الزيارة بنتيجة واضحة، وتبقى الفاتورة والتحصيل والمرتجع ضمن النماذج الرسمية الموجودة.
- نتيجة الفاتورة أو التحصيل أو المرتجع لا تُقبل من دون وجود المستند الرسمي المرتبط، والنتيجة المختلطة تحتاج نوعين مختلفين على الأقل.
- يمكن ربط مسودة فاتورة أو تحصيل أو مرتجع بـ `sales_visit_id`، مع التحقق من تطابق العميل والخط والمندوب والمستودع.
- العميل الجديد يُنشأ فعالاً ضمن خط المندوب، ويُضاف إلى رحلة اليوم المفتوحة عند وجودها.
- لا يمكن إنهاء الرحلة قبل اكتمال جميع الزيارات.
- لا يمكن تسليم نقد الإقفال عند وجود رحلة مبيعات غير مكتملة.

## المزامنة

يدعم Pull الكيانين `sales_journeys` و`sales_visits`. ويدعم Push Batch:

- إنشاء العميل.
- بدء وإنهاء رحلة المبيعات.
- بدء وإكمال الزيارة.
- العقود الحالية للفواتير والتحصيلات والمرتجعات مع `sales_visit_id`.

جميع عمليات الإنشاء الميداني تستخدم `client_reference` وتبقى قابلة لإعادة التشغيل بأمان.
