# عقد مزامنة الإغلاق اليومي الميداني

## القرار المعماري

الإغلاق اليومي سجل واحد مشترك. مندوب المبيعات المسؤول عن الخط يرسل قسمين مستقلين:

- `submit_inventory`: جرد مستودع السيارة.
- `submit_cash`: النقد الفعلي المسلم.

يبقى الإغلاق `draft` بعد القسمين، ثم تراجعه الإدارة وتؤكده وفق الصلاحيات الحالية.

## المتطلبات

- المستخدم يحمل دور `sales_representative` ويرتبط بالموظف المعين على الخط.
- الخط والسيارة ومستودع السيارة متطابقة وفعالة.
- توجد `SalesJourney` لليوم والخط والمندوب.
- يجب إنهاء الجولة قبل إرسال الجرد أو النقد.

## فتح الإغلاق

```text
POST /api/v1/operational/daily-closings/open-today
```

الفتح Online لأنه يحسم السياق من الخادم، ينشئ snapshot المواد والكميات المتوقعة، يحسب المجاميع ويعيد `sync_version`. لا ينشئ التطبيق إغلاقًا أو قائمة مواد من بيانات جزئية.

## Push Batch

يدعم entity `daily_closings` الإجرائين السابقين. كل عملية تحتاج:

```text
record_id
base_version
payload
```

مثال الجرد:

```json
{
  "items": [
    {"product_id": 10, "actual_quantity": "12.000", "notes": null}
  ]
}
```

مثال النقد:

```json
{
  "actual_cash_amount": "150000.00",
  "cash_notes": null
}
```

## قواعد الدمج والحماية

- تغير نسخة السجل بسبب تسليم قسم لا يمنع دمج القسم الآخر إذا بقي مستقلًا وصالحًا.
- يعيد الخادم حساب المجاميع قبل الحفظ.
- يجب إرسال قائمة مواد الجرد كاملة دون عناصر زائدة أو ناقصة.
- الملاحظات إلزامية عند فروقات الجرد أو النقد.
- يقفل كل قسم بعد أول تسليم ناجح.
- تغير حالة الإغلاق أو إعادة إرسال القسم نفسه يعاد كتعارض للمصالحة.
- لا يحدث اعتماد تلقائي ولا أثر مخزون جديد عند إرسال handover.
