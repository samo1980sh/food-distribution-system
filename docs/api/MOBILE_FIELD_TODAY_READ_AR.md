# Laravel — Field Today Read Foundation

## الهدف

إضافة عقد قراءة مخصص لتطبيق الهاتف:

```text
GET /api/v1/operational/today
```

العقد لا ينشئ رحلة ولا زيارة ولا تسليمًا، ولا يكتب في قاعدة البيانات.

## المصادقة

يستخدم نفس middleware الخاص بـMobile API:

- `auth:sanctum`
- `api.access`
- `api.token.touch`
- `throttle:mobile-api`

وهو متاح لدوري:

- `driver`
- `sales_representative`

## المعاملات الاختيارية

```text
role=driver|sales_representative
route_id=<active route id>
```

عند إرسال `route_id` يجب إرسال `role` حتى يكون الاختيار واضحًا للمستخدم الذي يجمع الدورين.

## اختيار خط اليوم

- الخط الفعّال المرتبط بالموظف والدور فقط.
- يطبق نطاقات الوصول الفعلية.
- `visit_days` الفارغة تعامل كجدول يومي حفاظًا على الخطوط التاريخية.
- إذا وجد خط واحد مجدول اليوم يتم اختياره.
- إذا وجد أكثر من خط مجدول تعاد حالة `route_selection_required`.
- إذا لم يوجد خط مجدول تعاد حالة `not_scheduled_today` دون اختراع تكليف.
- الخط المحدد خارج النطاق يعاد كـ404.

## الحالات

```text
ready
no_assignment
not_scheduled_today
route_selection_required
incomplete_assignment
```

## سياق المندوب

- الخط والسيارة ومستودع السيارة.
- عدد العملاء الفعالين المعينين للخط، وليس عدد الزيارات.
- ملخص فواتير اليوم حسب الحالة.
- ملخص تحصيلات اليوم حسب الحالة.
- ملخص مرتجعات اليوم حسب الحالة.
- حالة الإقفال الميداني إن وجد.

## سياق السائق

- الخط والسيارة ومستودع السيارة.
- ملخص الحمولات المعتمدة لليوم وحالة استلام العهدة.
- ملخص مخزون مستودع السيارة دون تكلفة.
- ملخص مصاريف السيارة الخاصة بالخط والسائق.
- حالة الإقفال الميداني إن وجد.

## غير مشمول

- رحلة يومية محفوظة.
- زيارة عميل أو ترتيب توقفات.
- مهمة حالية.
- إثبات أو حالة تسليم.
- أي عملية كتابة أو Offline Sync جديدة.
- أي Migration.


## دور الموظف داخل تعيين الخط

كل كائن موظف داخل:

```text
route.driver
route.sales_representative
candidate_routes[*].driver
candidate_routes[*].sales_representative
```

يعيد الحقل:

```text
assignment_role
```

وقيمته تكون `driver` أو `sales_representative` حسب موقع الموظف في تعيين الخط.

أما الحقل `type` فهو نوع الموظف الأساسي في البيانات الرئيسية، وقد يختلف عن `assignment_role` عندما يكون الحساب مرتبطًا بالدورين. لذلك يجب على تطبيق الهاتف الاعتماد على `context.role` و`assignment_role` لتحديد المسؤولية التشغيلية، وعدم استخدام `employee.type` وحده.
