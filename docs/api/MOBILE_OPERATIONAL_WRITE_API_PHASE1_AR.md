# Mobile Operational Write API

## الهدف

توفر واجهات الكتابة Online وOffline Queue فوق خدمات المجال الحالية دون تكرار قواعد المخزون أو الحسابات داخل Controllers.

## العمليات المدعومة

- العملاء: إنشاء عميل ميداني ضمن الخط الحالي.
- `SalesJourney`: فتح جولة اليوم، البدء، الإنهاء.
- `SalesVisit`: البدء والإكمال بنتيجة متوافقة مع المستندات.
- فواتير البيع: إنشاء نهائي بتأكيد وتسليم فوري، مع إجراءات الإدارة الحالية عند السماح.
- التحصيلات والمرتجعات: إنشاء وتعديل الحالات المسموح بها وإجراءات lifecycle.
- أوامر التحميل: استلام العهدة وتسجيل الفروقات.
- مصاريف السيارة: إنشاء وتعديل وحذف ما تسمح به الحالة.
- الإغلاق اليومي: الفتح، الجرد، النقد، والمراجعة الإدارية.

## المصادقة والنطاق

- Sanctum Bearer Token بقدرة `api:v1` وصلاحية `api.access`.
- الدور الميداني الوحيد `sales_representative`.
- Policies وData Scopes و`OperationalContextValidator` تتحقق من الخط والسيارة والمستودع والمندوب والعميل.
- السجل خارج النطاق يعاد 404، وقاعدة العمل غير المتحققة تعاد 409.

## Idempotency

عمليات الإنشاء تقبل `client_reference` ثابتًا لكل جهاز ونوع مستند:

- المرجع والبيانات نفسيهما يعيدان السجل السابق.
- المرجع نفسه مع payload مختلف يعيد `idempotency_conflict`.
- Offline push يستخدم `batch_id` و`operation_id` و`base_version`.

## الفاتورة والتسليم الفوري

- لا يقبل العميل رقم الفاتورة أو الحالة أو تكلفة المخزون.
- يحسب الخادم الأسعار والمجاميع وتوزيع التشغيلات.
- Final submit يؤكد الفاتورة مباشرة.
- Cash: المبلغ المدفوع وفق الإجمالي.
- Credit: `paid_amount=0` و`remaining_amount=total_amount` مع تطبيق credit limit.
- Partial: يحتفظ بالمبلغ المدفوع والمتبقي وفق القواعد الحالية.
- التأكيد يخصم مخزون السيارة فورًا، والإلغاء يعكس الأثر وفق guards الحالية.

## التحصيل والمرتجع

- التحصيل المرتبط بفاتورة يتحقق من العميل والرصيد والنطاق.
- المرتجع يتحقق من الفاتورة والكميات القابلة للإرجاع ويستخدم التكلفة الرسمية.
- آثار المخزون والذمم تنفذ عبر services الحالية داخل transactions.

## المصروف والإغلاق

- مصروف السيارة يملك route/vehicle/warehouse/representative من السياق الموثوق.
- إيصال المصروف اختياري وفق الأنواع والحجم المحددين في config.
- الجرد والنقد لا يرسلان قبل إنهاء `SalesJourney`.
- الإدارة تبقى مسؤولة عن اعتماد الإغلاق النهائي.

## Bootstrap وSync

يعيد bootstrap capabilities لكل module، وregistry versions، و`context_key`، وendpoints المزامنة. مصفوفة `actions` في كل Resource هي المرجع النهائي لأن حالة السجل تؤثر في الإجراء المتاح.
