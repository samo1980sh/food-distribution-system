# فصل المسؤوليات التشغيلية

## الهدف

يفصل النظام بين تنفيذ العمل الميداني وبين التخطيط والمراجعة الإدارية. الدور الميداني الوحيد هو `sales_representative`، ويستخدم تطبيق Flutter دورة عمل موحدة. تختص لوحة Filament بالإعداد والتخطيط والمراجعة والاعتماد والاستثناءات والتقارير.

## مصادر العمليات

- `mobile_sales`: العمليات التي ينشئها مندوب المبيعات من التطبيق.
- `office`: إدخال مكتبي مسموح، مثل بعض عمليات التحصيل.
- `admin_exception`: مستند إداري استثنائي مع سبب واضح.
- `system`: عمليات ينشئها النظام.
- `legacy`: سجلات عامة سابقة لتطبيق فصل المسؤوليات، ولا تمثل مسارًا ميدانيًا مستقلاً.

تسجل الفواتير والتحصيلات والمرتجعات والمصاريف والإغلاقات مصدر العملية ومنشئها لأغراض التدقيق.

## دورة المندوب الموحدة

```text
Vehicle Load
→ SalesJourney
→ Visits
→ Invoice / Immediate Delivery
→ Collections
→ Returns
→ Vehicle Expenses
→ Finish Journey
→ Vehicle Inventory
→ Cash Handover
→ Daily Closing
```

1. تجهز الإدارة أمر تحميل السيارة وتعتمده.
2. يستلم المندوب العهدة ويسجل أي فرق في الكميات.
3. يفتح `SalesJourney` لليوم ويبدأها بعد اكتمال استلام الحمولات.
4. ينفذ زيارات العملاء ويربط كل مستند بالزيارة والسياق الصحيح.
5. Final invoice submit يؤكد الفاتورة فورًا ويخصم مخزون السيارة؛ لا توجد مرحلة تسليم منفصلة.
6. تنشأ التحصيلات والمرتجعات والمصاريف وفق سياسات المجال والنطاق.
7. لا تنتهي الجولة قبل معالجة الزيارات المخططة.
8. بعد إنهاء الجولة يسلم المندوب جرد السيارة والنقد.
9. تراجع الإدارة الإغلاق اليومي وتؤكده أو تعالجه وفق الصلاحيات.

## مسؤوليات تطبيق Flutter

- تنفيذ الزيارات والمستندات الميدانية للمندوب المسؤول.
- العمل Online أو عبر Offline Queue والعقود الرسمية للمزامنة.
- احترام `context_key` وsync versions وidempotency references.
- عدم إرسال أرقام مستندات أو تكاليف مخزون أو ملكية تشغيلية غير موثوقة.
- عرض التعارضات وعدم تجاوز credit limit أو daily closing guards.

## مسؤوليات لوحة Filament

- إدارة البيانات الرئيسية والعملاء والمنتجات والمستودعات والسيارات والخطوط.
- تخطيط أوامر التحميل وتجهيزها واعتمادها.
- مراجعة الفواتير والتحصيلات والمرتجعات والمصاريف والإغلاقات.
- تنفيذ الإدخالات المكتبية أو الاستثنائية فقط عندما يسمح الدور، مع السبب المطلوب.
- إدارة التسويات الإدارية للمخزون والتقارير والتدقيق.

لا تنشئ لوحة الإدارة العمليات الميدانية الاعتيادية بدل المندوب، ولا تغير ملكية route/vehicle/warehouse المستمدة من السياق.

## قواعد المخزون والمال

- آثار الفاتورة والمرتجع وأمر التحميل تمر عبر خدمات المخزون داخل transactions.
- Cash/Credit/Partial والحد الائتماني وقواعد الإلغاء لا تتغير باختلاف واجهة الإدخال.
- تحصيل العميل يراجع الرصيد المتبقي والفاتورة والنطاق.
- فروقات الجرد والنقد تحتاج ملاحظات وتبقى للمراجعة الإدارية.
- حقول التكلفة والربح لا تعرض دون الصلاحيات المناسبة.

## الصلاحيات والنطاقات

- المندوب يرى خطه وعملاءه وسيارته ومستودع السيارة والعمليات المرتبطة بها فقط.
- المشرف مقيد بالمناطق والخطوط المسندة إليه.
- أمين المستودع مقيد بالمستودعات المسندة إليه.
- المحاسب يحتفظ بصلاحياته المالية الحالية.
- المدير وSuper Admin يخضعان للـPolicies والحواجز الخاصة بالسجلات الحساسة.

## فحص يدوي مختصر

1. حساب المندوب يفتح مساحة عمل موحدة واحدة.
2. أمر تحميل خارج خطه لا يظهر ولا يمكن استلامه.
3. الفاتورة النهائية تظهر `confirmed` ويخصم مخزون السيارة.
4. المستند الميداني يظهر بمصدر `mobile_sales`.
5. لا يمكن إنهاء الجولة مع زيارة معلقة.
6. لا يمكن إرسال الجرد أو النقد قبل إنهاء الجولة.
7. لا يمكن للمشرف إنشاء عملية ميدانية اعتيادية من Filament.
8. التسوية الإدارية للمخزون لا تحفظ دون سبب واضح.
